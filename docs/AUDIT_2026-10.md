# CareerPilot OS — Engineering Audit (2026-10-07)

Read-only audit performed before the "real AI / production completion" programme.
Each finding lists where it lives and the remediation status. Status values:
`OPEN` (not yet fixed), `FIXED` (fixed and verified by tests), `PARTIAL`.

**Remediation status updated 2026-10-08** after the completion programme. Verification used: backend
unit + integration tests (H2), AI-service unit tests, live AI tests against Ollama, the full Flyway
chain on PostgreSQL 16 with Hibernate schema validation, and a live HTTP end-to-end run
(`scratch/careerpilot_live_e2e.py`). Docker images could not be built in the verification
environment (Docker not installed); items that only Docker exercises are marked accordingly.

## G. Found during live verification (2026-10-08)

| # | Finding | Status |
|---|---|---|
| G1 | Flyway chain had never run on PostgreSQL: V5 re-added existing columns; 7 entity tables (`application_records`, `application_state_history`, `application_notifications`, `application_audit`, `application_approval_policies`, `application_retry_history`, `connector_configurations`) had no migration, so V16/V18 failed | FIXED (V5 `IF NOT EXISTS`, new `V15_1`; whole chain applied to a fresh PostgreSQL 16 DB; Hibernate `validate` passes) |
| G2 | String-mapped entity fields stored in `jsonb` columns → every insert fails on PostgreSQL | FIXED (`V26` converts them to `text`, as V14 did for agent tables) |
| G3 | V16 index on `application_state_history` silently skipped (name clash with V3) | FIXED (`V27`) |
| G4 | Every discovered job triggered 3 synchronous LLM calls inside the discovery transaction; every login started a full discovery; several syncs could run at once → DB pool exhaustion, requests failed with 401 | FIXED (analysis on demand, single-flight sync, login refresh throttled and gated by `careerpilot.discovery.enabled`) |
| G5 | Services held a DB transaction open across model calls (resume, job, company processing, interview coach, follow-up drafts, learning plans, HR classification) | FIXED (model calls run outside transactions; results persisted in short transactions) |
| G6 | `ApplicationSubmissionRegistry` reported submission connectors as `CONFIGURED`/`HEALTHY` without any check | FIXED (`REGISTERED`/`NOT_MONITORED`, manual sources `NOT_REQUIRED`/`NOT_APPLICABLE`) |
| G7 | JWT filter maps a DB outage to 401 (client sees "Authentication required" and logs out) | FIXED (503 `DATABASE_UNAVAILABLE`) |
| G8 | Refresh tokens (7 days) were accepted as bearer access tokens, and access tokens as refresh tokens | FIXED (`token_type` claim enforced on both paths; unit tests) |
| G9 | A candidate who applied on the company site could not record it: attestation from DISCOVERED/MATCHED/… stored evidence but the state never left DISCOVERED (no edge to SUBMITTED; ALREADY_APPLIED was a dead end); `submittedAt` was never set | FIXED (candidate-attestation edges in the single transition table; `submittedAt` set on first SUBMITTED; `ApplicationTrackingServiceTest`; live e2e asserts SUBMITTED and the later INTERVIEW transition) |
| G10 | Re-creating an application for the same job overwrote the existing record's state with ALREADY_APPLIED (bypassing the lifecycle authority, erasing e.g. INTERVIEW) | FIXED (idempotent: existing application returned unchanged) |
| G11 | Embedded Qdrant (local mode) is not thread-safe; concurrent index/search requests crashed with `sqlite3.InterfaceError` | FIXED (operations serialized in embedded mode; regression test fails without the lock) |
| G12 | Every discovered job was embedded concurrently on the shared async pool (thousands of postings) | FIXED (one low-priority indexing thread, bounded queue, after commit) |
| G13 | Skill normalization stripped non-ASCII letters ("Négociation" → "ngociation") and skills matched by raw substring ("r" matched "spring boot", "java" matched "javascript") | FIXED (Unicode-aware normalization; whole-term matching; unit tests) |
| G14 | Long postings could not be analysed on a CPU model: the LLM call was retried after a read timeout (doubling the wait), the backend surfaced the timeout as HTTP 500, and the whole 12k-character posting was sent | FIXED (no retry on read timeout; `AI_TIMEOUT`/`AI_PROVIDER_TIMEOUT` mapped explicitly; verbatim relevant-section reduction for local models; timeouts aligned across layers; gateway tests against a real HTTP server) |
| G15 | Small local models generated "practice" questions such as "What is the job title of this role?" | FIXED (prompt guidance + deterministic filter; test) |
| G16 | Job-parse responsibilities / qualifications / benefits were not grounding-checked | FIXED (same verbatim check as other extracted fields) |
